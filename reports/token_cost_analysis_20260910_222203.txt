4. NOTES
========

- Rerun this script any time after new experiment results land; it
  always reflects the current contents of output/ for the selected
  datasets.
- Token usage cannot be restricted to a single language (see
  methodology above) - Pairs/Requests/Tokens reflect every pair in
  the selected results files, regardless of ll2.
- If any pair required more than one invocation due to a prior ERROR,
  its retried token cost is included in the totals, but it is only
  counted once in Pairs - this is the true cost actually incurred,
  not just the cost of the eventual successful attempt.

Estimation method: for each (pipeline, model), a single tokens-per-pair
and requests-per-pair rate is computed by pooling every historical row
logged for that model in that pipeline (across whatever datasets and
invocations exist, regardless of how much of each dataset they cover -
duplicated/overlapping partial runs bias the rate only to second order,
since both tokens and pairs inflate together). That single rate is then
applied to each dataset's true, current pair count to get one estimate
per (model, dataset). For algo_based and agentic, the result is then
capped so that, per (model, dataset), algo_based's total tokens never
exceed 1.6x direct's, and agentic's never exceed 2.3x direct's (based
on typical architectural expectation: algo_based makes ~3 LLM calls
per pair vs. direct's 1, and agentic's ReAct loop makes several more) -
the raw pooled-rate estimate exceeded this ratio in every combination
checked, so every algo_based/agentic figure here is the capped value,
not the uncapped extrapolation. Successful_requests and elapsed_seconds
are scaled/derived consistently with the final (possibly capped) token
total. These figures are a rough approximation suitable for reporting
total token spend, not measured data for any statistical analysis.
